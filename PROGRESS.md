**B3 cancelled.** A separate `TimerController` state machine was never needed.
`IDLE → RUNNING ⇄ PAUSED → ENDED` is expressed by the session record itself —
`endedAt` and an open pause — and the transitions live on the store contract
(`startSession`, `pause`, `resume`, `endActiveSession`), held to one shared
suite by both implementations. A controller on top would have been a second
source of truth for state the data already carries.

## Current state

- `main` is green: **663 tests**, 28 suites, typecheck / lint / format clean.
- App builds and runs on **iPhone 17 Pro, iOS 26.5** (`npm run ios`).
- `main` is branch-protected: PR required, `Verify` check required,
  `enforce_admins: true`. Direct pushes are rejected.
- **Every screen in the app is built and verified on the simulator** against
  the real SQLite database, in both light and dark.
- Dark mode is reachable and persists. It was built in A2 and wired to nothing
  until C10a; the tab bar stayed light until `GlassView` was told the app has
  its own theme toggle.
- The core loop closes end to end: pick a category → timer → end → the session
  lands on Home, History and Insights, and survives a relaunch.
- Sessions, categories, tasks and preferences persist in SQLite at schema
  version 5.
- A write that cannot reach disk no longer takes the app down, and no screen
  says a thing was saved when it was not.
- A session that has run away with itself, or that starts in the future
  because the clock moved, is asked about on open — and kept unless the user
  says otherwise.
- Jest runs pinned to `America/New_York` so local-time and DST bugs
  cannot hide behind a UTC test machine.
- Every tree the suite renders is audited for what VoiceOver needs — a label,
  a trait, and a target a thumb can hit — so a control added without them
  fails the test that rendered it.

## Decisions that changed course

| Date       | Decision                                                                                                                                                                                                                                                                                               |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 2026-08-20 | Pink CTA keeps the design's white-on-pink despite failing AA. Owner's call, light mode only; dark mode already passes at 6.73:1.                                                                                                                                                                       |
| 2026-08-23 | **A3c cancelled.** Composite components are built when a screen first needs them, then promoted on second use.                                                                                                                                                                                         |
| 2026-08-23 | **Component gallery deleted.** The design system lives in code, not as a screen in the app. Components are reviewed on the screens that use them.                                                                                                                                                      |
| 2026-08-25 | **The locked decisions beat the design source three times.** The timer's `Goal · 3h 00m`, the Insights streak tile, and the green up-arrow week delta all imply a score. Dropped, replaced, and reworded as plain observation.                                                                         |
| 2026-08-25 | **No time or date pickers anywhere.** `@react-native-community/datetimepicker` is a native module and `pod install` is still broken, so editing times uses ±5/±15 nudges and date filtering is done by searching the day heading. Revisit once pods are fixed.                                         |
| 2026-08-25 | **B3 cancelled.** The timer state machine is the session record plus the store contract; a `TimerController` would be a second source of truth.                                                                                                                                                        |
| 2026-08-27 | **Offline indicator cut.** There is no network call anywhere in the app, so it would report a condition that cannot affect anything. Owner agreed. Idle detection cannot be built at all — React Native exposes no user-idle API — and moves to C10c alongside notifications-denied.                   |
| 2026-08-27 | **Suspiciously long is 8 hours of tracked time.** Owner's call. Worth restating plainly: a genuine eight-hour day trips it the moment it completes, so it is a prompt that keeps the session, never a cap.                                                                                             |
| 2026-08-27 | **The five writes a screen acts on report whether they landed.** A store that only broadcasts a failure does not stop the caller showing "Saved" and navigating away. The other ten stay `void`: their whole effect is a snapshot that does not move, so they cannot mislead anyone.                   |
| 2026-08-30 | **Accessibility is asserted on every render, not per screen.** A test per screen only covers the states someone thought to write a test for. Auditing the tree in a global teardown covers every state the suite already reaches, and made RNTL's own cleanup the thing to take over rather than race. |
| 2026-08-27 | **Every action offered has to be one the app can carry out.** Editing a running session can only nudge its start by 5 and 15 minutes, so "edit" is no answer to a 40-hour session or a clock a year out. Prompts offer one-tap repairs instead. Revisit when `pod install` allows a picker.            |
